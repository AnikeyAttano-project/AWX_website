## 1. Что такое админ-панель

Админ-панель — это отдельная страница (`admin.html`) для управления VPN-магазином. Через неё можно:

- Просматривать статистику (пользователи, ключи, выручка)
- Управлять пользователями (блокировка/разблокировка)
- Управлять ключами (продление, лимит устройств, удаление)
- Настраивать тарифы и группы тарифов (с инбаундами), триал, рефералку, демо-режим
- Смотреть и скачивать общий лог действий сайта

**Важно:** Админ-панель — это отдельный SPA (Single Page Application), не связан с основным сайтом. Она не содержит секретов и безопасна для размещения на публичном сервере.

## 2. Получение доступа

### 2.1. Получение API-ключа

В файле `.env` (в директории `backend/`) должен быть задан ключ:

```env
ADMIN_API_KEY=ваш_случайный_ключ_минимум_16_символов
```

**Как сгенерировать безопасный ключ:**

```bash
# Windows (PowerShell)
python -c "import secrets; print(secrets.token_urlsafe(32))"

# Linux/Mac
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

**Пример ключа:** `xK9mP2vL8nQ5wR7tY3uI6oA1sD4fG0hJ`

### 2.2. Проверка конфигурации

Убедитесь, что в `.env` есть:

```env
ADMIN_API_KEY=xK9mP2vL8nQ5wR7tY3uI6oA1sD4fG0hJ
```

**Важно:** Если `ADMIN_API_KEY` пустой или равен `""`, админ-панель полностью отключена (возвращает 503).

## 3. Вход в админ-панель

### 3.1. Открытие страницы

Откройте в браузере:

```
https://your-domain.com/admin.html
```

Или локально:

```
http://localhost:8000/admin.html
```

### 3.2. Авторизация

1. На странице появится поле для ввода ключа
2. Введите `ADMIN_API_KEY` из `.env`
3. Нажмите «Войти»

**Ключ хранится в localStorage** — при повторном открытии авторизация произойдёт автоматически.

### 3.3. Выход

Нажмите «Выйти» в боковом меню или очистите localStorage.

## 4. Разделы админ-панели

### 4.1. 📊 Dashboard (Главная)

Обзорная статистика:

- **Пользователи** — общее количество зарегистрированных
- **Ключи** — активные подписки в 3x-UI
- **Выручка** — сумма оплаченных заказов
- **Заказы** — общее количество заказов

### 4.2. 👥 Пользователи

Список всех зарегистрированных пользователей:

- **Поиск** — по email
- **Просмотр профиля** — email, дата регистрации, статус
- **Блокировка** — запрет доступа к сервису
- **Разблокировка** — восстановление доступа

**Как заблокировать пользователя:**
1. Найдите пользователя в списке
2. Нажмите «Заблокировать»
3. Подтвердите действие

Пользователь не сможет войти в аккаунт и использовать подписки.

### 4.3. 🔑 Ключи

Список всех выданных ключей (подписок):

- **Фильтр** — по статусу (активные, истёкшие, удалённые)
- **Продление** — продлить ключ на N дней
- **Устройства** — задать итоговый лимит устройств ключа (тестовый инструмент: обновляет лимит в 3x-UI и синхронизирует личный кабинет)
- **Удаление** — удалить ключ из 3x-UI и БД

**Важно:** Удаление ключа необратимо! Пользователь потеряет доступ. Лимит устройств нельзя поставить меньше базового лимита тарифа.

### 4.4. 📈 Статистика

Детальная статистика:

- **Заказы по дням** — график заказов за последние 30 дней
- **Выручка** — сумма по дням
- **Топ тарифов** — какие тарифы покупают чаще
- **Конверсия** — отношение заказов к оплатам

### 4.5. ⚙️ Настройки

Управление параметрами системы:

#### Тарифы

Изменение цен и условий:

```json
{
  "quantum_month": {"days": 31, "price": 300, "title": "Quantum Месяц", "devices": 5, "discount": 0, "inbounds": []},
  "quantum_quarter": {"days": 93, "price": 855, "title": "Quantum 3 Месяца", "devices": 5, "discount": 5, "inbounds": []},
  "quantum_halfyear": {"days": 186, "price": 1620, "title": "Quantum 6 Месяцев", "devices": 5, "discount": 10, "inbounds": []},
  "quantum_year": {"days": 365, "price": 2900, "title": "Quantum 12 Месяцев", "devices": 5, "discount": 20, "inbounds": []}
}
```

**Поля:**
- `days` — количество дней подписки
- `price` — цена в рублях
- `title` — название тарифа
- `devices` — количество устройств
- `discount` — скидка в процентах (для отображения)
- `inbounds` — инбаунды 3x-UI для тарифа. Пусто = наследовать от группы (или все из `XUI_INBOUND_IDS`)

#### Группы тарифов

Тарифы можно группировать (например Quantum). У каждой группы:

- **ID и название** — уникальный slug и отображаемое имя
- **Описание** — подпись на витрине
- **Инбаунды** — набор инбаундов для всей группы (если у тарифа своих нет)
- **Тарифы** — какие тарифы входят в группу

Кнопки: **Добавить группу**, **Удалить группу**, **Сохранить группы**.

**Приоритет инбаундов:** `тариф.inbounds` → `группа.inbounds` → все доступные. Клиент в 3x-UI создаётся только в этих инбаундах. Валидация: тарифы должны существовать, инбаунды — быть в списке доступных.

#### Триал (пробный период)

- **Включить/выключить** — активация бесплатного пробного периода
- **Длительность** — количество дней (по умолчанию 3)
- **Трафик** — лимит в GB (по умолчанию 25)
- **Устройства** — количество устройств (по умолчанию 1)

**Ограничения:**
- 1 триал на пользователя
- 1 триал на IP в 24 часа
- Требуется верифицированный email

#### Реферальная программа

- **Включить/выключить** — активация реферальной системы
- **Бонус за 1 уровень** — дни за приглашение напрямую
- **Бонус за 2 уровень** — дни за приглашение через реферала
- **Бонус за 3 уровень** — дни за приглашение через 2 уровней

**Как работает:**
1. Пользователь получает уникальный код (8 символов)
2. Приглашённые входят по `?ref=CODE`
3. При оплате реферер получает бонусные дни
4. До 3 уровней вложенности

#### Демо-режим

- **Включить/выключить** — показ/скрытие кнопки «Демо подписка» на витрине
- **Пароль** — защита от несанкционированного доступа

**Как работает:**
1. На витрине появляется карточка «Демо подписка»
2. Пользователь вводит пароль
3. Ключ выдаётся мгновенно без оплаты
4. Rate-limit: 3 демо-заказа в час с одного IP

**Для отладки:** включите `DEMO_MODE=true` в `.env`
**Для прода:** отключите через админку или `DEMO_MODE=false`

#### Логи

Общий лог действий сайта (`site_log`):

- **Просмотр** — последние 100–1000 записей (селектор сверху)
- **Обновить** — перечитать лог
- **Скачать лог** — выгрузить как текстовый файл

Записываются события: регистрация, вход, вход/привязка Telegram, создание заказа, выдача ключа (успех/ошибка), продление, покупка/отмена add-on, админ-действия. Лог хранит до 5000 записей (автоочистка).

## 5. Настройки

### 5.1. Изменение тарифов

1. Перейдите в «Настройки» → «Тарифы»
2. Измените цены или условия
3. Нажмите «Сохранить»

**Важно:** Изменения применяются к новым заказам. Уже оплаченные заказы не затрагиваются.

### 5.2. Настройка триала

1. Перейдите в «Настройки» → «Триал»
2. Включите/выключите триал
3. Настройте параметры (дни, трафик, устройства)
4. Нажмите «Сохранить»

### 5.3. Настройка рефералки

1. Перейдите в «Настройки» → «Рефералка»
2. Включите/выключите программу
3. Настройте бонусы по уровням
4. Нажмите «Сохранить»

### 5.4. Управление демо-режимом

1. Перейдите в «Настройки» → «Демо»
2. Включите/выключите демо-режим
3. Измените пароль (в `.env`)
4. Нажмите «Сохранить»

**Совет:** Для тестирования включите демо, для прода — отключите.

### 5.5. Настройка брендинга

1. Перейдите в «Настройки» → «Брендинг»
2. Укажите **название сайта** (показывается в логотипе, заголовке вкладки, футере)
3. Выберите **акцентный цвет** (HEX-пикер — перекрашивает кнопки и выделения)
4. Укажите **контакт поддержки** (email или ссылка в футере)
5. Нажмите «Сохранить брендинг»

Изменения применяются на витрине (`index.html`) и в личном кабинете (`account.html`) сразу после сохранения (при следующей загрузке страницы).

### 5.6. Экспорт / импорт настроек

Внизу раздела «Настройки» — карточка «Экспорт / импорт настроек»:

- **Экспорт (JSON)** — скачивает файл `awx-settings-backup.json` со всеми настройками (тарифы, группы тарифов, брендинг, триал, рефералка, промокоды)
- **Импорт из JSON** — выбираете файл, настройки восстанавливаются

**Использование:**
- Бэкап перед крупными изменениями
- Перенос настроек между инстансами (сменился сервер/домен)

Импорт валидирует данные: тарифы должны существовать, инбаунды — быть доступными, цвет — HEX, названия — непустые.

### 5.7. Платёжная система

В разделе «Настройки» — карточка «Платёжная система»:

1. Выберите провайдера: **Platega** или **ЮKassa**
2. Для ЮKassa укажите **shop_id** и **secret_key** (секрет не отображается после сохранения — поле можно оставить пустым, чтобы не менять)
3. Нажмите «Сохранить платёжную систему»

**Настройка ЮKassa:**
- Создайте платёж через API ЮKassa с redirect-confirmation (сайт делает это автоматически)
- В кабинете ЮKassa укажите вебхук: `https://ваш-домен/webhook/yookassa` (тип события `payment.succeeded`)

**Важно:** статус платежа всегда перепроверяется через API провайдера, поэтому поддельный или «сырой» вебхук не подтвердит заказ.

## 6. Безопасность

### 6.1. Защита API-ключа

- **Не раскрывайте** `ADMIN_API_KEY` публично
- **Используйте HTTPS** — без него ключ летит открытым текстом
- **Регулярно меняйте** ключ (раз в 3-6 месяцев)

### 6.2. Ограничение доступа

Админ-панель доступна:
- Только по API-ключу (X-Admin-Key header)
- Ключ проверяется на каждый запрос
- Используется `hmac.compare_digest` (защита от timing-атак)

### 6.3. Логирование

Все действия в админ-панели логируются:

```bash
# Просмотр логов
tail -f /var/log/awx-backend.log | grep "Admin"
```

### 6.4. Бэкапы

Перед серьёзными изменениями:

```bash
# Бэкап БД
cp backend/orders.db backend/orders.db.backup.$(date +%Y%m%d)

# Бэкап .env
cp backend/.env backend/.env.backup.$(date +%Y%m%d)
```

## 7. Решение проблем

### 7.1. «503 Service Unavailable»

**Причина:** `ADMIN_API_KEY` пустой или не задан.

**Решение:** Добавьте ключ в `.env` и перезапустите сервер.

### 7.2. «401 Unauthorized»

**Причина:** Неверный ключ или ключ не передан.

**Решение:** Проверьте `ADMIN_API_KEY` в `.env` и в поле ввода.

### 7.3. «Страница не найдена»

**Причина:** Файл `admin.html` не размещён в корне сайта.

**Решение:** Убедитесь, что `frontend/admin.html` доступен по URL `/admin.html`.

### 7.4. «Настройки не сохраняются»

**Причина:** Ошибка записи в БД.

**Решение:** Проверьте права на файл `backend/orders.db` и логи сервера.

### 7.5. «Ключи не отображаются»

**Причина:** Нет подключения к 3x-UI.

**Решение:** Проверьте `XUI_BASE_URL` и `XUI_API_TOKEN` в `.env`.
